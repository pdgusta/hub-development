Carta do plano · construção do hub

O plano de construção

O hub é costurado uma etapa por vez, de cima para baixo. Cada etapa usa a entrega de verdade das que vieram antes.

fio: uma entrega que desce para as etapas de baixo
carretel: a etapa onde a entrega nasce
nó: a etapa usa essa entrega
alinhavo: vai com exemplo, troca pelo real depois
portão: a próxima só começa quando esta passar
  • faixa = o nome antigo de cada pedaço do spec
  • hub de ensaio = um hub de teste, com notas de mentira
  • MCP = a porta pela qual os agentes leem e gravam no banco
  • porteiros (hooks) = scripts que o Claude Code, o Codex e o Copilot rodam antes ou depois de cada ação
  • integração = o ramo do git onde cada etapa pronta é juntada

Para a hora de cada etapa

Não se decide agora. Cada pergunta volta na ficha da sua etapa.

  • 0236 os bancos de ensaio no Docker
  • 1 copiar ou não os pilotos do vault
  • 4 autorização e cota para o teste único do gemini (pelo FreeLLMAPI)
  • 710 login do Claude Code, Codex e Copilot na pasta de usuário de ensaio
  • 8 três lacunas sem dono: o registro do aval para mudar o contrato; o modelo do verificador da guarda; o erro quando uma peça some

As quatro perguntas, na ordem da rodada

  1. A construção em etapas, uma depois da outra, nesta ordem

    etapa 0, depois as 10 faixas na ordem da fita, e a junção; cada uma usa a entrega real das de cima, com só dois alinhavos.

  2. A etapa 0 de provas de risco

    testa primeiro os dois bancos copiando entre si, as pastas com ponto de fora e os porteiros do Codex com acesso total.

  3. Os ramos de ontem

    guardados como ontem/faixa-NN para consulta; cada etapa recomeça da ponta da integração.

  4. Como você diz ao maestro como executar cada etapa

    antes de cada etapa, o maestro propõe a ficha (quem constrói, quem revisa, qual modelo, quantos no canvas) e você ajusta.

Fontes: proposta de etapas do maestro (16/10), spec da construção (o que cada faixa pede das outras), lições do revisor Prisma.
